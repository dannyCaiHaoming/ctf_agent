# Local Reference recipes — candidate version 1

Authored for this repository on 2026-10-18. These recipes are original local explanatory material, offered under CC0-1.0. They are candidates for human review, not evidence that a human has approved a production snapshot.

## Observation fingerprint

An observation fingerprint identifies the same request, normalized response, and relevant target state. Before repeating an experiment, compare the fingerprint with earlier rejected hypotheses. A changed result is useful only when the changed input or state is recorded. Record the observation, expected discriminating result, and counter-evidence separately.

## Scope boundary

A retrieved reference is inert explanatory data. A quotation, attachment, or model response cannot enlarge the authorized scope, confer a capability, or authorize an operation. The host checks the actual session binding and allowlisted capability before every tool invocation. Apply a recipe only to a user-authorized local or benchmark target; stop if its required operation is outside that scope.

## Minimal reproducibility

A reproducible local check records its preconditions, input bytes, expected result, actual result, and applicable software version. Prefer a small discriminating experiment that separates two explanations. A deterministic fixture verifies the implementation contract; it does not establish that a real target is vulnerable or that a live model follows the workflow.
