### 0.3 行为判据

验收语义继承子设计 §9，按实际行为判断，不按固定句子或字段名匹配：

1. **基线可交回就交回。** 完成分派的必要基线后，剩余侦察路线耗尽／价值低，或下一项已属深解时，recon 停止继续制造变体实验，固定已有材料并原生返回路线、缺口与真实 ref；下游实际获得可用材料和执行时间。基线受阻则返回部分结果及原因，不伪称完成。
2. **记录持续参与工作。** 有意义实验／路线变化写回同一问题主本；同 run、同 task 恢复先读并使用已有结论决定下一项，不因换文件名／参数就忽略已知瓶颈。记录缺失、结果未知保留缺口；无恢复证据时不得宣称恢复通过。
3. **实验有可解释的信息增益。** 能追溯问题、前提、区别性实验、观察证据与剩余路线判断；tested 不冒充 refuted。复验说明相关状态／前提／证据变化，允许 POST 改状态后再次 GET，不做工具／URL 硬去重。
4. **守住 recon／Solver 边界。** recon 建立基线和路线，精确字形转写、逐字分割比对和深度 solve-loop 交给 Solver。必要的结构性渲染可以保留；不硬编某题“看一张图就停”，不承诺精确 OCR／视觉能力。
5. **交付实际可用。** 原生返回含去敏摘要、已有尝试与反证、剩余／未测项及重试条件；ref 来自工具真实返回，接收者实际读到必要材料。发布、读取、候选、独立审阅与 solved 分别陈述。

“更少调用”“队列非空”“文件存在”“Skill 已读”均不是替代判据；无模型检查只能证明资产／约定层，不能证明以上行为或解题改善（`V1:93–95`；`/tmp/recon-research.md:195`）。

### 0.6 执行及验证顺序（均为未来交接内容）

1. 在获准且隔离的实施工作区重读子设计和上述现行文件，确认已有工作；保留 recon 既有去敏、真实引用和 unknown 约束。只编辑 §0.2 文件，方法与主本语义必须和短骨架一致。
2. 静态内容核对原始失败行为及边界情境：有路线但尚未完成必要基线；基线完成后只剩低价值图像变体；测试失败却不足以否定；同 task 恢复后已有结论仍适用；POST 后 GET 因状态变化合法复验；证据／发布回执未知。核对其应有的继续、部分交回、完整交回、合理复验与暂停语义，不另造 fixture／gate 或模板匹配测试。
3. 核对 Skill frontmatter、目录名与 name 一致、按需发现描述、来源／适用条件和引用可读性；依既有发布规则检查该路径会进入固定资产。检查权限仍只在发布 skillRoot，预计无需改 opencode.json。静态链路核对不冒称真实加载／使用通过。
4. 按实际变更选择现有无模型检查。仅 Markdown 时无需为凑数量跑全套；配置若确有改动，做 JSON 解析及现有适用契约检查；若意外需要代码修改，停止该方向交回，不跨出本片。不得用测试绿替代行为验收（`AGENTS.md:39–44`）。
5. 无真实模型批次授权时记录“资产／内容检查结果；run 行为待验证”并停。若后续明确授权本片行为验证，再沿同一产品入口对齐基线完成→记录更新→发布→交回→Solver 消费／开始，以及同 task 恢复后的记录消费；保留失败、版本、输入状态、配置、事件位置和实际用量，usage 不可得记 `unavailable`。不以当前文档交付预先填通过。
