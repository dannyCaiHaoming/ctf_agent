# G：配額與數值預設验证 plan

**依据：** [G design](../specs/2026-10-23-design-v1-g-solver-minimal.md) §3.3、§4.4、§5.6、§7.2、§10；總design §1.4。只验证该未定项，不把候选写成已采用。
**目标：** 分開驗證配額機制與預設數值適用性；不以合成負載替代真實求解校準。
**执行：** 专属 gpt-6.1-sol session，独立 worktree。原型代码从已核对的 g-c-rpc-slow-tools 工作区按需复制，保留来源/hash；当前 design 从主区复制，不使用 HEAD 的旧文档。

## 边界
- 不 commit/push，不合并或覆盖主区产品代码；不调用真实模型。运行仅本地fixture与loopback确定性替身。
- 允许本项必要可逆原型和无模型验证。Docker仅本任务命名资源，不改宿主网络/账户、不删其他任务资源；非root/无Docker socket等产品约束不得放宽。
- 先在自己的 design 写候选、问题与去向，再做验证；有外部契约/架构冲突或真实环境不足就报告，不虚构通过。
- 主要验证文件：tests/contract/g-resource-limits.test.ts；必要小型fixture。只在对应路径做必要改动，不扩展别的未定项。

## 验证步骤
- [ ] 盤點128MiB工作區、HTTP8、job每session2/每題8、timeout及收尾值的執行者與未實作處；在自己design提出run級工具次數/時間計量候選，不按模型成本混算。
- [ ] 用有界確定性負載驗證邊界以下/等於/超過、並發保留、取消/失敗/unknown是否正確結算；覆蓋覆寫文件、HTTP落盤與job直接寫入對總量的影響。
- [ ] 比較宿主帳本與OS配額能保證的界面，記錄是否依賴OS隔離候選；無硬限制時明確不能稱總量已強制，不為測試建立大體積壓力。
- [ ] 查鏡像固定PATH和重啟/恢復計量要求；只推薦有證據的預設或保留待定，不自行給真實run新增成本預算。

**完成判定：** 每一上限有可信計量及拒絕/結算證據；產品數值未經適用性驗證則仍標提案，不能全數定稿。
