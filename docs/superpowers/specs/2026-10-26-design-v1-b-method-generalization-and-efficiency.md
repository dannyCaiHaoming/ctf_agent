## 2. 要解决什么，达成后有什么效果

**唯一目标：** 将反复有用的推理和实验方法做成可按需使用的短 Skill／Reference，使 Agent 在未见题目上更快取得有区分力的观察和可验证候选，同时保持正确性、scope 与验证标准。

Skill 回答“在什么情况下怎样推进”；Reference 提供具体知识、版本、适用条件与反例。角色负责选择和协作，host 保持工具、权限与状态责任。预期减少无依据的尝试、重复读取和不必要的交接；不承诺预设加速比例，不追求单纯减少调用数，也不把提早失败称为变快。

## 3. 内容选择与落地方式

**先明确能力需要，再选文件：** 历史缺陷修补与用户确认的主动能力建设都可作为依据，不能要求每项新能力先证明旧 run 出错。历史修补从一段具体失败／低效轨迹判断是没有知识、没有发现知识、没有正确运用，还是工具／权限不足。已有正确内容未被读取，先修发现与触发；知道方法但没得到执行事实，交相关接口设计；确实没有通用方法才补内容。一次只选择一个可独立比较的缺口，不先铺满 Web／Misc／Crypto 知识库。

| 候选内容 | 适用问题与做法 | 结果去向 |
| --- | --- | --- |

**要补的实质内容。** Reference 用“已知入口／前提 → 两种可能解释 → 最小对照 → 实际观察 → 能支持什么与下一步”组织，以下三类各有可操作的例子，而不是再次罗列通用原则：

| 问题与竞争解释 | 最小方法与知识 | 结果去向和反例 |
| --- | --- | --- |
| 输入被原样回显、编码显示、规范化／转换，还是仅在不同展示层看起来变化？ | 用不含秘密的独特文本标记先定位输入落点；比较同一证据的原保存 bytes、响应类型及明确观察到的表示层，再选一个普通字符变化。用自造的 `amber&17` 与 HTML 字符引用示例说明 bytes 和显示文字不同 | 编码差异不证明代码执行，未找到标记不自动证明过滤。只得到 HTML bytes 时不声称看到了 DOM 或浏览器执行；只有响应预览时先读已保存必要部分，不以重发代替续读 |
| 输入被当作数据、受特定语法解析、被计算，还是只是碰巧出现某个数字／错误？ | 当源码、文档化格式或已有错误提供解析线索时，用无副作用的字面量基线与有不同预测结果的简单计算对照；改变操作数，必要时加字面量负对照。给一个明确标为 Jinja 3.1.x 默认语法的算术例子，仅说明假设如何检验 | 语法错误只支持输入影响了解析相关路径，不证明任意执行；单次出现预期数值不能确认引擎或求值位置。要检查字面量回显、应用计算、缓存／静态结果等替代解释；前提不符就退回入口／材料检查，不枚举 payload 或升级到命令、文件读取 |

## 7. 方向与优先序（2026-10-28，r7 驱动，参考外部 CTF agent 设计）

r7（[路线优先级增量](2026-10-28-design-v1-b-evidence-to-action-route-priority.md)、[路线复核 §5](2026-10-25-design-v1-negative-evidence-and-route-review.md)）暴露的核心失败是「线索与能力在手却发散、不收敛」。对照公开 CTF/pentest agent 设计（以下为训练知识，截至 2026-01，细节待原文核对）：PentestGPT 以显式 **PTT（任务/线索树）** 让每步从树上选、避免走丢；Cybench 显示**子任务分解/有界推进**显著提升解题；EnIGMA 强调**高杠杆专用工具与 ACI**、减少往返；D-CIPHER 多 agent 但有**协调与交接损耗**。它们对「发散不收敛」的有效解不是外部看门狗，而是**外显、强制消费的计划/线索状态 + 强工具**。

**据此确定投资优先序（取代此前以 D/B 为重心的框定）：**

1. **显式线索/假设帐本，强制消费（最高）。** 让 solver 每步从一个持久、外显的线索/假设列表里选下一步，未测的具体线索（如 r7 的 `/admin/chal/delete`）始终可见、挡在通用枚举之前。**复用现有 `ctf_progress_note`／progress 帐本与 Recovery Critic**，关键是把它从「事后记录」变成「选下一步的强制依据」，而非新建系统。这是你 §3.2「固定思路」直觉的领域验证版。**详细设计见 [显式线索/假设帐本与强制消费](2026-10-28-design-v1-b-lead-ledger-convergence.md)**（已核实 solver 当前无 progress 权限、「强制消费」对 LLM 本质是遵循问题，故倾向「自动注入上下文」而非让模型主动调工具读）。
2. **高杠杆工具，砍往返（次高）。** r7 的 Domain Solver 78 次、全 run 108 次 HTTP 加几十次搜索。与其加角色，不如给更强原语（如结构化枚举、源码→路由映射），直接压低预算内往返。按实际缺口增量，不预造工具箱。
3. **有界推进 + 边界反思（D，节拍）。** [路线复核 §5](2026-10-25-design-v1-negative-evidence-and-route-review.md) 的候选 D，作为帐本的节拍器，使既有交回边界停滞规则自然触发。
4. **宿主停滞信号（B，仅兜底）。** §5 候选 B 需新通知路径与更粗信号，成本高、治标；只作兜底，不作主力。
