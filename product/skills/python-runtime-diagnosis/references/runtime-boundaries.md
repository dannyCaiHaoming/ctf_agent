# Python 運行時的控制層與結論邊界

按需讀對應小節。本文只說明各層能支持什麼結論，不提供繞過方法。

## 1. 控制層對照

| 層 | 典型觀察 | 能支持的結論 | 還缺什麼才能確定 |
| --- | --- | --- | --- |
| 宿主或用戶授權 | 宿主回覆 `denied:` 與原因，或目標不在授權範圍 | 該操作在本次授權內不可做 | 無；授權不足本身就是停止該操作的理由 |
| Python 審計 hook | 例外在呼叫敏感操作時拋出，訊息或堆疊指向 hook | 有 hook 擋下這個事件 | hook 註冊層（Python 或 C）、作用的解釋器、事件名稱 |
| 作業系統存取控制 | `PermissionError`／`OSError`，errno 為 `EACCES` 或 `EPERM` | 當前身份對該對象沒有該操作的權限 | 執行身份、對象的擁有者與權限位、是否還有其他存取控制 |
| 程式本身錯誤 | 型別、參數或路徑錯誤，與權限無關 | 呼叫方式有誤 | 正確的 API 用法與版本差異 |

宿主的拒絕來自 host，不是 Python 或作業系統的行為；三者分開記錄。hook 拋出的例外類型由 hook 自己決定，可能看起來像其他層的錯誤；來源不明時保留 unknown。

## 2. 審計機制的作用範圍（CPython 3.8 起）

- Python 層的 `sys.addaudithook` 只加到當前（子）解釋器。
- C 層的 `PySys_AddAuditHook` 對整個運行時生效，並在 Python 層 hook 之前呼叫。
- hook 加入後不能移除或替換。
- 官方審計事件表只涵蓋 CPython 運行時與標準庫；其他實作與第三方套件以各自文檔為準。
- 官方文檔明言審計 hook 主要用於記錄，不適合用來實作沙箱。

推論：審計層的結論不能當成存取控制的結論，反之亦然。只知道一層的 hook 時，不判斷另一層或另一個解釋器的行為。

## 3. 作業系統存取控制

權限拒絕說明當前身份對該對象沒有該操作的權限。它不說明部署錯誤、不說明權限已改變，也不說明題目不可解；它與審計層互相獨立，審計 hook 不改變行程身份或檔案權限。

## 4. 不能外推

| 觀察 | 不能推出 |
| --- | --- |
| 審計沒有記錄或沒有攔截 | 操作被允許，或沒有其他控制 |
| Python 層的狀態改變 | 作業系統權限改變 |
| 權限拒絕 | 部署錯誤、環境不一致或整題不可解 |
| 版本、實作或 hook 註冊層未知 | 另一個解釋器或另一層的行為 |
| 技術上可行 | 已獲授權 |

## 5. 寫入工作簿

- facts：操作、層、原始錯誤與證據 ref；只寫看到的。
- hypotheses：至少一個替代解釋，例如「審計 hook 擋下」與「存取控制拒絕」並列，直到有區分證據。
- questions：最小缺失證據，例如解釋器實作與版本、例外的拋出位置、執行身份與對象權限位。
- 下一步限於現有授權；授權外的操作寫成停止理由。
